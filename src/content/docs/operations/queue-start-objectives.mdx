Start by checking the services and the error returned to your client. Keep the server, embedding worker, application jobs, and scheduler running with the same database and queue settings.

## Cannot connect

1. Run `curl http://localhost:5150/_ping` on the server host. Replace the URL if you changed the port.
2. If that fails, check whether the server is running and inspect its logs.
3. If local access works but remote access fails, check the published Docker port, `BINDING`, firewall, and reverse proxy. Use the server's address, not the client's `localhost`.
4. For MCP, use the `/mcp` endpoint and an `Authorization: Bearer <api-key>` header. Check hostname and browser-origin settings in [Configuration](../../configuration/#server-address).

`/_ping` checks the HTTP process, not whether searches or jobs work.

## Authentication or permission errors

For `401`, check that the key is complete, not revoked, and sent in the bearer header. For `403` or a tool permission error, ask the administrator whether the key allows that operation. Creating schemas and importing data need `schema` access; reading needs `read` access.

Do not recreate the installation to fix a client key. Ask for a replacement key and update the MCP client.

## Search returns 503

Check the embedding worker first, not just the server:

```sh
docker compose ps
docker compose logs --tail 100 worker
```

For packages:

```sh
sudo systemctl status yorishiro-worker
sudo journalctl -u yorishiro-worker -n 100 --no-pager
```

Wait for the first model download to finish. Check available disk space, model file permissions, and connectivity to an external embedding service. If embeddings are disabled with `none`, enable a provider before using semantic search.

Search also returns `503` during a workspace reindex. Wait for successful completion. After fixing provider failures, use the [embedding recovery instructions](../../configuration/embedding/#change-the-embedding-model).

## A saved item does not appear in search

Ask your assistant to retrieve it by ID or list the entities. Search data updates in the background, so a successful save does not mean similarity search is ready immediately. If the delay persists, inspect the embedding worker logs.

## Import or other work stays queued

Imports, filling defaults, undo, and Enterprise inference need the application-job worker. The embedding worker does not run them.

```sh
docker compose logs --tail 100 jobs
```

For packages:

```sh
sudo systemctl status yorishiro-jobs yorishiro-scheduler
sudo journalctl -u yorishiro-jobs -u yorishiro-scheduler -n 100 --no-pager
```

Check that `start --worker=job-target:shared` is running and that all services use the same database and queue. For an import, poll `import_job_status` with the returned `job_id` rather than submitting the same import repeatedly.

For dedicated Enterprise pools, check both the [declared target and running workers](../../configuration/workers-and-queues/#worker-targets). A declared target does not prove a worker is running. If limits are enabled, work can wait for existing jobs to finish.

## A service will not restart

Fix the error in the logs before retrying. For a systemd unit that reached its restart limit:

```sh
sudo systemctl reset-failed yorishiro-worker
sudo systemctl start yorishiro-worker
```

Replace the unit name with the failing service. Check configuration syntax, connection URLs, and read permissions. Avoid deleting database or queue files as a troubleshooting step.

## Ask for help

Include the release tag, edition, installation method, database and queue types, failing operation, and relevant error messages. Remove API keys, passwords, and private content. Say which services are running and whether the problem also occurs with a direct API request.
