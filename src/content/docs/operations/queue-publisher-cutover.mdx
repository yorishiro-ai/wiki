Before updating, read the chosen release's notes and back up your database and configuration. A content export is useful for moving information, but it is not a complete installation backup.

## Back up

- **SQLite:** stop all four services before copying the data directory. Keep the database, separate queue database, and any SQLite sidecar files together. Do not copy only a live `.sqlite3` file.
- **PostgreSQL:** use your database backup procedure, such as `pg_dump`, and test restoring it to a separate database. Preserve the queue too if it uses a separate database or Valkey.
- **Configuration:** save your Compose file or `/etc/yorishiro/production.yaml`, connection settings, and credentials in a protected backup.

Record the image or package version alongside the backup. Model files can be downloaded again, but preserving them avoids a large download.

## Update Docker Compose

1. Stop clients from submitting new work and let pending jobs finish where possible.
2. Stop the services and take your backup. Keep the existing volumes.
3. Change the image tag in `compose.yml` to the chosen version, using the same version and edition for all four services.
4. Pull and restart:

```sh
docker compose pull
docker compose up -d
docker compose ps
docker compose logs --tail 100 app worker jobs scheduler
```

Check `/_ping`, an authenticated read, and a search before resuming clients. Do not run `docker compose down -v`: it deletes named volumes.

## Update packages

Stop new work, stop all four services, and take a backup. Install the new package using the [package installation commands](../../installation/packages/). Compare your configuration with the new `/etc/yorishiro/production.yaml.example`, then restart:

```sh
sudo systemctl restart yorishiro yorishiro-worker yorishiro-jobs yorishiro-scheduler
```

## Restore or change storage

Test restoration separately before replacing your installation. A database migration may prevent an older binary from reading an upgraded database; changing the image tag back is not a recovery plan. Follow release-specific guidance and restore the matching backup when required.

For moving workspace content, use [Export and import](../../guides/import-export/). Changing `DATABASE_URL` or `QUEUE_URL` does not migrate data or pending jobs. Do not switch queues while work is pending without a tested migration procedure.

Older documentation referred to publisher-epoch cutover tasks. Those commands are not available in the current product; do not use them for an update.
