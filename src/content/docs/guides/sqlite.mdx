For your own personal Yorishiro installation, start with the default SQLite storage. It saves information on one host in one tenant without a separate database service. If someone else runs the server, you do not need to choose the storage yourself.

## What you can do

Save, update, list, and delete information; connect items with relations; use templates; search by meaning; and export or import workspace content. Keep both worker services running for background operations.

## Limits to check

- One tenant only, including Enterprise. Use PostgreSQL for multiple tenants.
- Data-field containment filters are unavailable. Omit `filter` in searches and listings, or use PostgreSQL when you need it.
- SQLite writes one operation at a time. Many concurrent writes can wait on one another.
- Similarity search scans vectors, so large workspaces can become slow.
- Template marketplace browsing and template-version publishing are unavailable.
- Infer-fill runs at most one job per workspace at a time.

## Keep files together

The default production data file is `/var/lib/yorishiro/yorishiro.sqlite3`. The queue uses a separate file, `/var/lib/yorishiro/yorishiro_queue.sqlite3`. Never point both URLs at the same file.

Keep the server and workers on the same host with the same file paths. Valkey can replace the queue, but it does not make a SQLite database accessible to a worker on another host.

## Move beyond SQLite

Use PostgreSQL when you need more than one tenant, remote workers, content filters, or better write concurrency. Changing `DATABASE_URL` does not copy existing information. Test an [export and import](../import-export/) into your new installation, and keep a [full backup](../../operations/queue-publisher-cutover/) until you have verified it.
