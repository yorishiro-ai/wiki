The installation examples work without a custom configuration. Change only what you need. If someone else operates your server, ask them to change server settings; your MCP client only needs its URL and API key.

## Configuration files

| Installation | Configuration                                                                                 |
| ------------ | --------------------------------------------------------------------------------------------- |
| Docker       | Environment entries in `compose.yml`, or `/app/config/production.yaml`                        |
| Packages     | Copy `/etc/yorishiro/production.yaml.example` to `/etc/yorishiro/production.yaml` and edit it |
| Source       | `config/development.yaml`; use `LOCO_ENV=production` for `config/production.yaml`             |

The production example reads the environment variables listed here. If you replace a value with a literal in YAML, that entry no longer reads its environment variable. Restart the affected services after a change, keeping database and queue settings consistent across all four.

A replacement `production.yaml` must be complete: it is not merged with the packaged file. A `production.local.yaml` beside the base configuration overrides selected values. `LOCO_CONFIG_FOLDER` selects a different configuration directory. See [Packages](../installation/packages/#configuration) for file permissions and database changes.

## Server address

| Production variable           | Default            | Set it when                                                                                          |
| ----------------------------- | ------------------ | ---------------------------------------------------------------------------------------------------- |
| `BINDING`                     | `localhost`        | Use `0.0.0.0` to accept connections from outside the host or container                               |
| `PORT`                        | `5150`             | You need another listening port                                                                      |
| `HOST`                        | `http://localhost` | Set the full URL users connect to, including port if needed                                          |
| `YORISHIRO_MCP_ALLOWED_HOSTS` | Unset              | Add allowed MCP hostnames, comma-separated, when using a restricted listener behind another hostname |
| `YORISHIRO_ALLOWED_ORIGINS`   | `[]`               | Allow browser clients from exact origins, as a JSON array                                            |

`HOST` does not change where the server listens. The [Docker examples](../installation/docker-compose/) explicitly set `BINDING=0.0.0.0` and `HOST=http://localhost:5150`.

For browser clients on another origin, set `YORISHIRO_ALLOWED_ORIGINS`, for example `["https://assistant.example.com"]`. This is separate from MCP hostname validation and does not replace an API key. A wildcard listener (`0.0.0.0` or `::`) accepts any MCP Host; a restricted listener accepts loopback and its bind address plus explicitly allowed hosts.

## Database and queue

| Production variable    | Default                                                  | Use                                                                           |
| ---------------------- | -------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `DATABASE_URL`         | `sqlite:///var/lib/yorishiro/yorishiro.sqlite3?mode=rwc` | Data storage; use a `postgres://` URI for PostgreSQL                          |
| `YORISHIRO_QUEUE_KIND` | Follows the database URL                                 | `Sqlite`, `Postgres`, or `Redis` for Valkey and other Redis-compatible queues |
| `QUEUE_URL`            | Provider default                                         | Queue connection URI                                                          |

Use SQLite with a separate SQLite queue file, PostgreSQL with a PostgreSQL queue, or either database with Valkey. The SQLite database and queue must not share a file. Do not place SQLite files on another host for remote workers.

PostgreSQL needs the `vector` and `pg_trgm` extensions. The [Compose example](../installation/docker-compose/#postgresql-and-valkey) includes their setup. Changing a connection URL does not move existing data; see [Export and import](../guides/import-export/).

## Tenants

Community and unlicensed Enterprise allow one tenant. With a valid Enterprise licence, `YORISHIRO_MAX_TENANTS` sets a higher limit; `0` means unlimited and disables first-run setup. Negative values are invalid. SQLite always allows only one tenant.

## Search and sign-in limits

| Production variable                     | Default  | Meaning                                                |
| --------------------------------------- | -------- | ------------------------------------------------------ |
| `YORISHIRO_SEARCH_TOKENS_PER_MINUTE`    | `100000` | Shared API/MCP search budget per workspace per minute  |
| `YORISHIRO_AUTH_RATE_LIMIT_MAX`         | `10`     | Sign-in and sign-up requests per client IP in a window |
| `YORISHIRO_AUTH_RATE_LIMIT_WINDOW_SECS` | `60`     | Sign-in window in seconds                              |

The search budget uses an estimate based on query size, not a provider's token bill. If requests are rate-limited, reduce frequency before raising the limit. Sign-in values must be positive.

## API keys

Owners and admins can manage workspace keys through the API:

| Request                                             | Result                                            |
| --------------------------------------------------- | ------------------------------------------------- |
| `POST /api/api-keys` with `{"name":"My assistant"}` | Creates a key; save `full_key` from this response |
| `GET /api/api-keys`                                 | Lists keys without secrets                        |
| `DELETE /api/api-keys/{id}`                         | Revokes a key immediately                         |

Names must contain 1 to 100 characters. Revoking the key your client uses disconnects that access, so update the client with a replacement first.

## Logging

Production logs are JSON. Use `LOG_LEVEL=info` normally; use `debug` while diagnosing a problem, then change it back. `RUST_LOG` takes priority if set. See [Troubleshooting](../operations/queue-start-objectives/) for commands to read logs. Remove credentials before sharing logs or configuration.

## Time zone

Set `YORISHIRO_TIMEZONE=Asia/Tokyo` in the production environment, or change `settings.timezone` in your configuration. The default is `UTC`; use an IANA time zone name. Restart all services with the same setting.

This changes displayed timestamps, not when recorded events occurred. An invalid name prevents startup.
