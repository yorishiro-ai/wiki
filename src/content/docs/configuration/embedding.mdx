Embeddings let you find information by meaning rather than exact words. The standard installation uses a local model and requires no external API key. Keep the [embedding worker](../workers-and-queues/) running.

## Choose a provider

| Choice                    | Set in the production environment                                       | Result                                                                           |
| ------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Local model               | `YORISHIRO_EMBEDDING_PROVIDER=local`                                    | Default. Runs multilingual-e5-base on the embedding worker.                      |
| OpenAI-compatible service | Set both `YORISHIRO_EMBEDDING_BASE_URL` and `YORISHIRO_EMBEDDING_MODEL` | Uses your endpoint and model. Add `YORISHIRO_EMBEDDING_API_KEY` if required.     |
| Disabled                  | `YORISHIRO_EMBEDDING_PROVIDER=none`                                     | Save and retrieve items without loading a model. Semantic search is unavailable. |

Setting both the external endpoint and model takes priority over the provider variable, even `none`. To disable an external provider, remove those two values too.

For Docker Compose, add settings to the shared `x-yorishiro.environment` block. For packages, edit `settings.embedding` in `/etc/yorishiro/production.yaml`. Restart the services after changing settings.

## Local model

The default model supports multiple languages, including Japanese. On first startup, the embedding worker downloads about 1 GiB into `models/multilingual-e5-base/` under its working directory. Docker uses `/app/models/`; packages use `/var/lib/yorishiro/models/`. Preserve this directory to avoid downloading again.

For offline use, put both `model.safetensors` and `tokenizer.json` in that directory. The worker must be able to read them. Providing only one prevents startup. See the [Compose mounting instructions](../../installation/docker-compose/#use-a-local-embedding-model-offline).

`YORISHIRO_LOCAL_MODEL` defaults to `multilingual-e5-base`, the supported local model. `YORISHIRO_LOCAL_MAX_SEQUENCE_LENGTH` defaults to `512` and accepts `16` to `512`. Leave these unchanged unless you need to limit input length.

## External service

Use an OpenAI-compatible embeddings service, such as an appropriately configured Ollama, LM Studio, vLLM, or OpenAI endpoint. Set the endpoint URL, model name, credentials, and model output size together.

| Variable                                    | Use                                                                               |
| ------------------------------------------- | --------------------------------------------------------------------------------- |
| `YORISHIRO_EMBEDDING_BASE_URL`              | Your service URL, reachable from the embedding worker                             |
| `YORISHIRO_EMBEDDING_MODEL`                 | The service's embedding model name                                                |
| `YORISHIRO_EMBEDDING_API_KEY`               | Service credential; leave empty if not required                                   |
| `YORISHIRO_EMBEDDING_DIMENSIONS`            | Output vector size; default `768`. Must match the model.                          |
| `YORISHIRO_EMBEDDING_SEND_DIMENSIONS_PARAM` | Default `false`. Enable only if the service expects a `dimensions` request field. |

Inside Docker, `localhost` means that container, not the host or another service. Use an address reachable from the container. Enterprise can also [choose a provider per workspace](../enterprise/#per-workspace-embedding-provider).

## Change the embedding model

Back up your data before changing the provider or model. Restart with the new settings. Yorishiro schedules reindexing when it detects a changed workspace model; keep the embedding worker and scheduler running.

To request a full reindex yourself:

```sh
yorishiro task reindex_embeddings workspace_id:<uuid>
```

Run the task with the same configuration as your installation. In Compose, use `docker compose exec app yorishiro task reindex_embeddings workspace_id:<uuid>`.

Search in the workspace returns `503` during reindexing and becomes available after it completes successfully. For missing embeddings after an import or a provider failure, run `yorishiro task resync_embeddings workspace_id:<uuid>` after fixing the cause.

## Search timing

New or updated items can take time to appear in similarity results. You can still retrieve an item by ID. Search returns `503` if the worker or provider cannot produce the query embedding in time; it does not silently become text-only search.

The production variable `YORISHIRO_QUERY_EMBEDDING_TIMEOUT_MS` defaults to `15000` and supports up to `120000`. Check worker logs and provider connectivity before increasing it. See [Troubleshooting](../../operations/queue-start-objectives/).
