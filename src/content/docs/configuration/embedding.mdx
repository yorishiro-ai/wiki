Search can find notes with similar meaning even when the words differ. The standard installation uses a local model, so you do not need an external API key. If someone else runs your server, ask them to choose or change the service on this page. Server operators must keep the [embedding worker](../workers-and-queues/) running.

## Choose a provider

| Choice                    | Set in the production environment                                       | Result                                                                           |
| ------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Local model               | `YORISHIRO_EMBEDDING_PROVIDER=local`                                    | Default. Runs multilingual-e5-base on the embedding worker.                      |
| OpenAI-compatible service | Set both `YORISHIRO_EMBEDDING_BASE_URL` and `YORISHIRO_EMBEDDING_MODEL` | Uses your endpoint and model. Add `YORISHIRO_EMBEDDING_API_KEY` if required.     |
| Disabled                  | `YORISHIRO_EMBEDDING_PROVIDER=none`                                     | Save and retrieve items without loading a model. Semantic search is unavailable. |

Setting both the external endpoint and model takes priority over the provider variable, even `none`. To disable an external provider, remove those two values too.

For Docker Compose, add settings to the shared `x-yorishiro.environment` block. For packages, edit `settings.embedding` in `/etc/yorishiro/production.yaml`. Restart the services after changing settings.

## Local model

The default model supports multiple languages, including Japanese. On first startup, the embedding worker downloads about 1 GiB into `models/multilingual-e5-base/` under its working directory. Docker uses `/app/models/`; packages use `/var/lib/yorishiro/models/`. Preserve this directory to avoid downloading again.

For offline use, put both `model.safetensors` and `tokenizer.json` in that directory. The worker must be able to read them. Providing only one prevents startup. See the [Compose mounting instructions](../../installation/docker-compose/#use-a-local-embedding-model-offline).

`YORISHIRO_LOCAL_MODEL` defaults to `multilingual-e5-base`, the supported local model. `YORISHIRO_LOCAL_MAX_SEQUENCE_LENGTH` defaults to `512` and accepts `16` to `512`. Leave these unchanged unless you need to limit input length.

## External service

Use an OpenAI-compatible embeddings service, such as an appropriately configured Ollama, LM Studio, vLLM, or OpenAI endpoint. Set the endpoint URL, model name, credentials, and model output size together.

| Variable                                    | Use                                                                               |
| ------------------------------------------- | --------------------------------------------------------------------------------- |
| `YORISHIRO_EMBEDDING_BASE_URL`              | Your service URL, reachable from the embedding worker                             |
| `YORISHIRO_EMBEDDING_MODEL`                 | The service's embedding model name                                                |
| `YORISHIRO_EMBEDDING_API_KEY`               | Service credential; leave empty if not required                                   |
| `YORISHIRO_EMBEDDING_DIMENSIONS`            | Output vector size; default `768`. Must match the model.                          |
| `YORISHIRO_EMBEDDING_SEND_DIMENSIONS_PARAM` | Default `false`. Enable only if the service expects a `dimensions` request field. |

Inside Docker, `localhost` means that container, not the host or another service. Use an address reachable from the container. Enterprise can also [choose a provider per workspace](../enterprise/#per-workspace-embedding-provider).

### Ollama

Install [Ollama](https://ollama.com/), start its server, and download an embedding model, not a chat model:

```sh
ollama pull nomic-embed-text
curl --fail-with-body http://localhost:11434/v1/embeddings \
  -H 'Content-Type: application/json' \
  -d '{"model":"nomic-embed-text","input":["A test note"]}'
```

For Yorishiro running on the same host, use:

```yaml
YORISHIRO_EMBEDDING_PROVIDER: openai
YORISHIRO_EMBEDDING_BASE_URL: http://localhost:11434/v1
YORISHIRO_EMBEDDING_MODEL: nomic-embed-text
YORISHIRO_EMBEDDING_API_KEY: ""
YORISHIRO_EMBEDDING_DIMENSIONS: "768"
YORISHIRO_EMBEDDING_SEND_DIMENSIONS_PARAM: "false"
```

These are environment entries, not a complete Yorishiro configuration file. The example model produces 768 dimensions. For another model, check its output size and change the setting. See [Ollama's OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility).

### LM Studio

In [LM Studio](https://lmstudio.ai/), download and load an embedding model, then start its local API server from the Developer section. The usual port is `1234`; use the address shown by your server. Get the exact model identifier:

```sh
curl --fail-with-body http://localhost:1234/v1/models
```

Use that identifier and the model's output dimensions:

```yaml
YORISHIRO_EMBEDDING_PROVIDER: openai
YORISHIRO_EMBEDDING_BASE_URL: http://localhost:1234/v1
YORISHIRO_EMBEDDING_MODEL: <embedding-model-id>
YORISHIRO_EMBEDDING_API_KEY: ""
YORISHIRO_EMBEDDING_DIMENSIONS: "<model-output-dimensions>"
YORISHIRO_EMBEDDING_SEND_DIMENSIONS_PARAM: "false"
```

Replace both placeholders. If you enabled API authentication in LM Studio, supply its token instead of an empty key. Verify the model with the Ollama curl example, changing the port and model and adding a bearer header if required. See [LM Studio embeddings](https://lmstudio.ai/docs/developer/openai-compat/embeddings).

### Hosted API or another OpenAI-compatible server

For example, OpenAI's `text-embedding-3-small` can return 1536-dimensional vectors:

```yaml
YORISHIRO_EMBEDDING_PROVIDER: openai
YORISHIRO_EMBEDDING_BASE_URL: https://api.openai.com/v1
YORISHIRO_EMBEDDING_MODEL: text-embedding-3-small
YORISHIRO_EMBEDDING_API_KEY: ${EMBEDDING_API_KEY}
YORISHIRO_EMBEDDING_DIMENSIONS: "1536"
YORISHIRO_EMBEDDING_SEND_DIMENSIONS_PARAM: "true"
```

In Compose, supply `EMBEDDING_API_KEY` through your deployment's secret handling; do not commit its value. Hosted services receive the text being embedded and may charge for requests. Other services, including vLLM, need their own embedding model, URL, credential, and output size; a chat-completions endpoint alone is not enough.

Yorishiro appends `/embeddings` to the base URL. Include `/v1` when the service requires it, but do not include `/embeddings` itself. These examples call `/v1/embeddings`, not Ollama's native `/api/embed` endpoint.

### Apply the settings

For Compose, merge the chosen environment entries into `x-yorishiro.environment`, keeping the existing database and queue entries. Then run `docker compose up -d` to recreate services with the new settings. A plain `docker compose restart` does not apply changed environment values.

If Ollama or LM Studio runs on the Docker host, replace `localhost` with `host.docker.internal`. On Linux Docker Engine, add this to `x-yorishiro`:

```yaml
extra_hosts:
  - "host.docker.internal:host-gateway"
```

The model server must listen on an address reachable from containers, not only its loopback address. Use Ollama's `OLLAMA_HOST` setting or LM Studio's network-serving option, and restrict access with your firewall. For another Compose service, use its service name and container port instead.

For packages, edit the existing `settings.embedding` block in `production.yaml`, using fields rather than environment-variable names. For Ollama on the same host:

```yaml
settings:
  embedding:
    provider: openai
    base_url: http://localhost:11434/v1
    model: nomic-embed-text
    api_key: ""
    dimensions: 768
    send_dimensions_param: false
```

Merge this into the existing configuration; do not replace the whole file or remove other `settings` entries. Restart all four packaged services. No `yorishiro.env` file is needed. If the workspace already has embeddings, follow the model-change procedure below, then test a search and check the embedding worker logs.

## Change the embedding model

Back up your data before changing the provider or model. Restart with the new settings. Yorishiro schedules reindexing when it detects a changed workspace model; keep the embedding worker and scheduler running.

To request a full reindex yourself:

```sh
yorishiro task reindex_embeddings workspace_id:<uuid>
```

Run the task with the same configuration as your installation. In Compose, use `docker compose exec app yorishiro task reindex_embeddings workspace_id:<uuid>`.

Search in the workspace returns `503` during reindexing and becomes available after it completes successfully. For missing embeddings after an import or a provider failure, run `yorishiro task resync_embeddings workspace_id:<uuid>` after fixing the cause.

## Search timing

New or updated items can take time to appear in similarity results. You can still retrieve an item by ID. Search returns `503` if the worker or provider cannot produce the query embedding in time; it does not silently become text-only search.

The production variable `YORISHIRO_QUERY_EMBEDDING_TIMEOUT_MS` defaults to `15000` and supports up to `120000`. Check worker logs and provider connectivity before increasing it. See [Troubleshooting](../../operations/queue-start-objectives/).
