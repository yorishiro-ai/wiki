構成を1つ選び、`compose.yml`に保存してください。`<VERSION>`を選んだ[リリースタグ](https://github.com/yorishiro-ai/yorishiro/releases)に置き換えます。例はCommunity向けです。Enterpriseではイメージ名の末尾を`-ce`から`-ee`に変えてください。

## SQLite

外部データベースを用意せず、個人で使う場合の構成です。

```yaml
x-yorishiro: &yorishiro
  image: ghcr.io/yorishiro-ai/yorishiro:<VERSION>-ce
  restart: unless-stopped
  environment:
    BINDING: 0.0.0.0
    HOST: http://localhost:5150
    YORISHIRO_EMBEDDING_PROVIDER: ${YORISHIRO_EMBEDDING_PROVIDER:-local}
  volumes:
    - data:/var/lib/yorishiro
    - models:/app/models

services:
  app:
    <<: *yorishiro
    ports:
      - "5150:5150"
  worker:
    <<: *yorishiro
    command: ["start", "--worker=worker-target:shared"]
    healthcheck:
      disable: true
    depends_on:
      app:
        condition: service_healthy
  jobs:
    <<: *yorishiro
    command: ["start", "--worker=job-target:shared"]
    healthcheck:
      disable: true
    depends_on:
      app:
        condition: service_healthy
  scheduler:
    <<: *yorishiro
    command: ["scheduler"]
    healthcheck:
      disable: true
    depends_on:
      app:
        condition: service_healthy

volumes:
  data:
  models:
```

## PostgreSQLとValkey

複数のテナントや別マシンのワーカーにはPostgreSQLを使います。キューはRedis互換のValkeyです。起動前に、データベースのパスワード2か所の`change-me`を変更してください。

`compose.yml`と同じ場所に`init-extensions.sql`を作成します。

```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
```

PostgreSQLがこのファイルを実行するのは、データ用ボリュームが空のときだけです。既存のデータベースでは先に管理者に拡張の有効化を依頼してください。

```yaml
x-yorishiro: &yorishiro
  image: ghcr.io/yorishiro-ai/yorishiro:<VERSION>-ce
  restart: unless-stopped
  environment:
    BINDING: 0.0.0.0
    HOST: http://localhost:5150
    DATABASE_URL: postgres://yorishiro:change-me@db:5432/yorishiro
    YORISHIRO_QUEUE_KIND: Redis
    QUEUE_URL: redis://valkey:6379
    YORISHIRO_EMBEDDING_PROVIDER: ${YORISHIRO_EMBEDDING_PROVIDER:-local}
  volumes:
    - models:/app/models

services:
  db:
    image: pgvector/pgvector:pg18
    restart: unless-stopped
    environment:
      POSTGRES_USER: yorishiro
      POSTGRES_PASSWORD: change-me
      POSTGRES_DB: yorishiro
    volumes:
      - pg-data:/var/lib/postgresql
      - ./init-extensions.sql:/docker-entrypoint-initdb.d/init-extensions.sql:ro
    healthcheck:
      test: ["CMD", "pg_isready", "-U", "yorishiro"]
      interval: 5s
      timeout: 3s
      retries: 5
  valkey:
    image: valkey/valkey:9.1.2
    restart: unless-stopped
    command: ["valkey-server", "--appendonly", "yes"]
    volumes:
      - valkey-data:/data
    healthcheck:
      test: ["CMD", "valkey-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 5
  app:
    <<: *yorishiro
    ports:
      - "5150:5150"
    depends_on:
      db:
        condition: service_healthy
      valkey:
        condition: service_healthy
  worker:
    <<: *yorishiro
    command: ["start", "--worker=worker-target:shared"]
    healthcheck:
      disable: true
    depends_on:
      app:
        condition: service_healthy
      valkey:
        condition: service_healthy
  jobs:
    <<: *yorishiro
    command: ["start", "--worker=job-target:shared"]
    healthcheck:
      disable: true
    depends_on:
      app:
        condition: service_healthy
      valkey:
        condition: service_healthy
  scheduler:
    <<: *yorishiro
    command: ["scheduler"]
    healthcheck:
      disable: true
    depends_on:
      app:
        condition: service_healthy

volumes:
  pg-data:
  valkey-data:
  models:
```

キューにもPostgreSQLを使う場合は、`YORISHIRO_QUEUE_KIND`、`QUEUE_URL`、`valkey`サービス、そのボリューム、`depends_on`内のValkeyへの依存を削除します。キューも`DATABASE_URL`を使うようになります。

## 起動して接続する

`compose.yml`があるディレクトリで実行します。

```sh
docker compose up -d
docker compose ps
docker compose logs --tail 100 worker
```

埋め込みワーカーは初回に約1 GiBのモデルをダウンロードします。サーバーなど、ほかのサービスはモデルを読み込みません。意味による検索を使わず保存を試す場合は、代わりに`YORISHIRO_EMBEDDING_PROVIDER=none docker compose up -d`を実行してください。

[初回起動](../first-run/)に進み、`http://localhost:5150`を使います。別のアドレスから接続する場合は、`HOST`を利用者向けのURLに変更してください。データベースとキューの設定は4つのサービスでそろえます。

## データを残す

`docker compose down`は名前付きボリュームを削除せずに停止します。ボリュームとデータを削除する意図がない限り、`-v`を付けないでください。イメージの更新はバックアップの代わりにはなりません。[更新とバックアップ](../../operations/queue-publisher-cutover/)を参照してください。

## ローカルモデルをオフラインで使う

ホストに両方のファイルを配置します。

```text
models/multilingual-e5-base/model.safetensors
models/multilingual-e5-base/tokenizer.json
```

既存の`x-yorishiro.volumes`リスト内で、`models:/app/models`を`./models:/app/models:ro`に置き換えます。SQLiteの`data:/var/lib/yorishiro`など、ほかの項目は残してください。`docker compose up -d worker`でワーカーを作り直します。

コンテナのユーザーが両方のファイルを読める必要があります。片方だけだと埋め込みワーカーが起動しません。プロバイダーの選択は[埋め込み](../../configuration/embedding/)を参照してください。
