先に[Docker Compose](../docker-compose/)か[パッケージ](../packages/)でインストールしてください。管理者からURLとAPIキーを受け取っている場合は、手順4へ進めます。

例では`http://localhost:5150`を使います。別のサーバーへ接続する場合は、そのURLに置き換えてください。アカウントはWeb画面ではなくAPIで作成します。

## 1. サーバーを確認する

```sh
curl http://localhost:5150/_ping
```

成功すればサーバーが応答しています。検索には埋め込みワーカーも必要です。初回は約1 GiBのモデルをダウンロードするため、検索を試す前にワーカーの起動を待ってください。

## 2. 最初のアカウントを作成する

セットアップが必要か確認します。

```sh
curl http://localhost:5150/setup/status
```

`setup_required`が`true`なら、メールアドレス、パスワード、名前を置き換えて実行します。

```sh
curl -X POST http://localhost:5150/setup \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"choose-a-password","display_name":"You"}'
```

返された`api_key`をパスワードマネージャーなどに保存してください。表示されるのはこのときだけです。レスポンスにはユーザー、テナント、ワークスペースのIDも含まれます。

`409`が返る場合は、すでにテナントがあります。管理者にアクセスを依頼してください。`YORISHIRO_MAX_TENANTS=0`の場合はセットアップを利用できません。

## 3. APIキーを使う

保存したキーでリクエストします。

```sh
curl http://localhost:5150/api/api-keys \
  -H 'Authorization: Bearer <api-key>'
```

`<api-key>`を保存したキーに置き換えます。山括弧は含めません。キーを持つ人はその権限を使えるため、公開しないでください。

## 4. MCPクライアントを接続する

リモートHTTPサーバーとカスタムヘッダーに対応するMCPクライアントに、次を設定します。

| 設定         | 値                          |
| ------------ | --------------------------- |
| サーバーURL  | `http://localhost:5150/mcp` |
| ヘッダー名   | `Authorization`             |
| ヘッダーの値 | `Bearer <api-key>`          |

クライアントが別のマシンで動く場合は、`localhost`をサーバーのアドレスに置き換えてください。提供された環境を利用する場合は、管理者から受け取ったHTTPSのURLを使います。設定画面はクライアントごとに異なりますが、`/mcp`のURLとBearerヘッダーは共通です。

再接続し、AIアシスタントにスキーマの一覧を尋ねてください。`list_schemas`を呼び出せれば接続できています。新しいワークスペースなら一覧が空でも正常です。

続けて[AIアシスタントで使う](../../guides/using-yorishiro/)でメモの保存と検索を試してください。エラーが出る場合は[トラブルシューティング](../../operations/queue-start-objectives/)を参照してください。

## 接続先と権限を確認する

接続後はアシスタントに次のように依頼してください。

> 接続中のテナントとワークスペースを確認してください。メモを保存できるかも教えてください。まだ変更はしないでください。

`whoami`で接続先、`capabilities`でキーの権限情報を確認できます。操作の許可は本人の役割やライセンスなどにも左右されるため、フラグが満たされていても実行できない場合があります。

複数のワークスペースがある場合は、`discover_workspaces`で候補を確認できます。同じ名前があればUUIDで区別してください。候補の一覧を取得しただけではアクセス権は付きません。ワークスペース専用のキーでは接続先を切り替えられません。Enterpriseのテナント用キーでは、許可されたワークスペースのUUIDを`X-Workspace-Id`に指定します。詳しくは[APIキー](../../guides/api-keys/)を参照してください。

共同利用を始めるときは[アクセス管理](../../guides/access-management/)、ログインできないときは[トラブルシューティング](../../operations/queue-start-objectives/#ログインの復旧)へ進んでください。
