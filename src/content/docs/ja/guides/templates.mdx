保存したい情報に合うテンプレートを選んでください。アシスタントに`list_templates`で組み込みテンプレートを一覧してもらい、`template_id`を指定した`create_schema`でスキーマを作成します。作成には`schema`権限が必要です。最初の例は[AIアシスタントで使う](../using-yorishiro/)に掲載しています。

| テンプレート              | 用途                                                                                                   | エンティティタイプ                                                          |
| ------------------------- | ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| `general-notes`           | タグとリンクを持つ一般的なノート                                                                       | note                                                                        |
| `software-adr`            | ソフトウェアプロジェクトのアーキテクチャ決定、サービスカタログ、技術スタック                           | decision, service, incident                                                 |
| `task-management`         | 期限、依存関係、クライアント、マイルストーン、担当、作業セッション、引き継ぎを持つプロジェクトとタスク | project, task, client, milestone, assignee, work_session, handoff           |
| `research-knowledge-base` | 論文、著者、概念、実験、データセット                                                                   | paper, author, concept, experiment, dataset                                 |
| `game-dev-lore`           | ゲームで共有する設定資料。キャラクター、場所、勢力、アイテム、イベント、用語集の項目、アセット         | character, location, faction, item, event, term, asset                      |
| `creative-writing`        | 長編の執筆。キャラクター、場所、組織、アイテム、章、シーン、プロットスレッド、イベント                 | character, location, organization, item, chapter, scene, plot_thread, event |
| `trpg-campaign`           | TRPGキャンペーンの運営。キャラクター、場所、勢力、アイテム、セッション、クエスト、遭遇                 | character, location, faction, item, session, quest, encounter               |
| `worldbuilding`           | 非推奨。キャラクター、場所、勢力、アイテム                                                             | character, location, faction, item                                          |

各テンプレートはエンティティ間のリレーションタイプも定義しています。

テナント独自のライブラリにあるテンプレートは`list_template_library`でUUIDを調べて`template_id`に指定します。保存の前にスキーマを確認し、実際の項目名とリレーションの型を使うよう依頼してください。

## 非推奨のテンプレート

`worldbuilding` は非推奨です。新しく作成する場合は、`creative-writing`、`trpg-campaign`、`game-dev-lore` のいずれかを使ってください。`template_id` の値 `worldbuilding` は引き続き使え、既存のスキーマも変更されません。

## スキーマのバージョンとarchive

`create_schema`はワークスペースのスキーマ、または次の不変のバージョンを作成します。過去の定義は書き換えません。変更前に`get_active_schema`、`get_schema_by_id`、`list_schemas`で定義を確認してください。

`archive_schema`には`schema`スコープが必要です。指定したバージョンをarchiveしても、エンティティ、過去の定義、紐付け、forkの参照は削除されません。古いバージョンが再び有効になることもありません。その後に同名で作成すると次のバージョンに進みます。archiveは物理削除ではありません。

## テナントのtemplate library

テナントのAdmin/Ownerは、ツールのスコープ要件のもとで`create_template_library_item`、`update_template_library_item`、`delete_template_library_item`、`fork_template_library_item`を使い、共有定義を管理できます。これらはtemplate libraryの資源であり、物理的なPostgreSQL schemaではありません。ライブラリの定義を変更・削除しても、ワークスペースのコピーと既存のバージョンは別に保持されます。

Enterpriseのスキーマfork管理は、テナントのライブラリやMarketplace公開とは別の機能です。[Enterprise設定](../../configuration/enterprise/#テンプレートの更新とスキーマのフォーク)を参照してください。
