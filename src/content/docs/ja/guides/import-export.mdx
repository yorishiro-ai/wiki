別のワークスペースに情報を移したいときは、ファイルに書き出して取り込みます。書き出せるのは、APIキーでアクセスするワークスペースの保存形式、保存した項目、そのつながり（スキーマ、エンティティ、リレーション）です。ユーザー、APIキー、サーバー設定は含まれず、環境全体のバックアップにはなりません。全体のバックアップは[更新とバックアップ](../../operations/queue-publisher-cutover/)を参照してください。

## ワークスペースを書き出す

`read`権限のキーを使います。URLとキーを置き換えてください。

```sh
curl --fail-with-body http://localhost:5150/api/export.jsonl \
  -H 'Authorization: Bearer <api-key>' \
  -o workspace.jsonl
```

ファイルを使う前にコマンドの成功を確認してください。内容は平文なので、エクスポートを公開しないでください。

アシスタントに次のように依頼することもできます。

> 接続中のワークスペースをexport_jsonlで書き出してください。成功したことを確認してから、保存するJSON Linesの内容を渡してください。

`read`権限が必要です。受け取ったJSON Linesは、取り込むまで内容を変えずに保管してください。ファイル全体が1つのJSON値ではなく、1行に1件ずつ記録されています。

RESTとMCPのどちらも、上限は8 MiBかつ合計10,000レコードです。スキーマとリレーションも件数に含みます。どちらかを超えるとRESTでは`422`、MCPではツールエラーになり、途中までの文書は返りません。上限を超える場合は、サーバー運用者に情報を移す方法を相談してください。ページ単位の一覧は内容の確認に使えますが、そのまま取り込めるエクスポートではありません。スキーマの一覧には定義の全文が含まれず、リレーションを移す際には取り込み先の情報同士のつながりも保つ必要があります。

ファイルには名前・バージョン順のスキーマ、その後にエンティティ、リレーションが記録されます。書き出している間に変更すると内容が整合しない場合があり、ある時点の状態を固定したファイルにはなりません。環境全体の整合したバックアップが必要な場合は、サーバー運用者に[更新とバックアップ](../../operations/queue-publisher-cutover/)の手順を依頼してください。

## ワークスペースに取り込む

取り込み先のワークスペースの`schema`権限のキーを使います。先に空のワークスペースで試してください。使用中のワークスペースに同じファイルを繰り返し投入しないでください。

```sh
curl --fail-with-body -X POST http://localhost:5150/api/import.jsonl \
  -H 'Authorization: Bearer <destination-api-key>' \
  -H 'Content-Type: application/x-ndjson' \
  --data-binary @workspace.jsonl
```

レスポンスには`job_id`が含まれます。受付済みという意味で、完了ではありません。アプリケーションジョブのワーカーを起動して、状態を確認します。

```sh
curl --fail-with-body http://localhost:5150/api/import-jobs/<job-id> \
  -H 'Authorization: Bearer <destination-api-key>'
```

`completed`になるまで待ってください。`failed`なら、再実行前にエラーとログを確認します。ワーカーはレコードをまとめて取り込み、レコードのエラーがあれば取り込みをロールバックします。

## アシスタントから取り込む

接続済みのアシスタントには次のように依頼できます。

> このJSON Linesを取り込みたいです。取り込み先のワークスペースを確認してから実行し、完了したかも確認してください。

アシスタントは`import_jsonl`で取り込みを依頼し、返されたIDで`import_job_status`を確認します。どちらも`schema`権限が必要です。チャットへ全文を送る前に、ファイルの大きさがクライアントの制限に収まるか確認してください。

取り込み後は検索データの再生成が必要な場合があります。埋め込みが足りなければ、管理者に取り込み先の[resync_embeddings](../../configuration/embedding/#埋め込みモデルを変更する)の実行を依頼してください。検索だけでなく、一覧やID指定の取得でも結果を確認します。
