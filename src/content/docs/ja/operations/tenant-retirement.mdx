利用をやめるときは、まず必要な情報を[書き出し](../../guides/import-export/)、サーバー運用者と[バックアップ](../queue-publisher-cutover/)を確認してください。テナントを無効にしてもデータは消えません。完全に削除したい場合は、別途サーバー運用者へ依頼します。

## 無効化前の確認

テナントのOwnerは接続済みのアシスタントに次のように依頼できます。

> このテナントの利用を終了したいです。残るデータ、未完了の処理、ほかのワークスペースにコピーされたスキーマへの影響を確認してください。まだ無効化しないでください。

`tenant_retirement_inventory`で、保持される記録、未完了の処理、ほかのテナントでも使う本人アカウント、外部のスキーマforkを確認します。RESTでは`GET /api/tenants/current/retirement`を使います。一覧は確認時点の情報です。確認しただけで、その後の操作が許可されるわけではありません。外部のforkは完全削除前に対応が必要な場合があります。

## データを残して無効化する

無効化できるのはOwnerだけです。テナントのAdminにはできません。`whoami`で名前とUUIDを確認し、残す情報の保存が済んでから`disable_tenant`を依頼してください。確認用の`confirmed_tenant_id`には対象のテナントUUIDを指定します。APIでは`POST /api/tenants/current/disable`に同じ値を送ります。

無効化すると、操作に使ったキーも含めてテナントのキーがすべて失効し、接続できなくなります。未完了の処理は取り消されますが、データと利用枠の使用量は残ります。プランや手動上限の空きを増やすための操作ではありません。

すでに認証済みのリクエストは完了する場合があります。進行中の外部呼び出しも、すべて止まる保証はありません。

## operatorによる完全削除

完全削除は取り消せません。必要な情報を残し、サーバー運用者に対象のUUIDを渡して依頼してください。通常のREST/MCPのキーでは実行できません。最後のワークスペースを通常の削除操作で消すこともできません。

サーバー運用者は目的の環境の設定を選んでoperator CLIを使います。共有する例に本番のUUIDや秘密値を含めないでください。

| タスク                      | 指定する値と確認事項                                                                       |
| --------------------------- | ------------------------------------------------------------------------------------------ |
| `inspect_tenant_retirement` | `tenant_id`で保持データと影響を確認                                                        |
| `disable_tenant`            | `tenant_id`と同じ値を`confirmed_tenant_id`に指定。データは保持                             |
| `delete_tenant`             | 先に無効化し、`tenant_id`と同じ値を`confirmed_tenant_id`に指定。テナントのデータを完全削除 |

完全削除で実際のデータが削除されると、使用していたテナントの利用枠が解放されます。APIキーの履歴も削除されます。ただし、ほかのテナントでも使う本人アカウントと、秘密値を含まない廃止の記録は残ります。

## 本人アカウントの削除

テナントから退会することと、本人アカウントを削除することは別です。メンバーを削除すると本人のテナントのキーは失効しますが、共有アカウントは残ります。テナントの管理者はほかのテナントの本人アカウントを削除できません。

本人アカウント自体の削除はサーバー運用者に依頼してください。運用者は`list_users`で対象を確認し、どのテナントにも所属していないことを確かめてから`delete_user`を使います。`user_id`と`confirmed_user_id`には同じUUIDが必要です。残った本人のキーを先に失効させ、紐付けを外してからアカウントを削除します。

## 上限を確認する

無効化後も残る使用量、プランによる上限、手動で設定した上限は別です。上限を変えたいだけなら、廃止ではなく[Enterprise設定](../../configuration/enterprise/#プランポリシーとジョブの制限)を確認してください。
