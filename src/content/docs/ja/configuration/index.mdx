導入例は独自の設定ファイルなしで動きます。必要な項目だけ変更してください。ほかの方が運用する環境では、サーバー設定の変更を管理者に依頼します。MCPクライアントに必要なのはURLとAPIキーです。

## 設定ファイル

| 導入方法   | 設定先                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------ |
| Docker     | `compose.yml`の環境変数、または`/app/config/production.yaml`                               |
| パッケージ | `/etc/yorishiro/production.yaml.example`を`/etc/yorishiro/production.yaml`にコピーして編集 |
| ソース     | `config/development.yaml`。`LOCO_ENV=production`なら`config/production.yaml`               |

productionの例は、このページに示す環境変数を読み込みます。YAMLの値を固定値に置き換えると、その項目は環境変数を参照しなくなります。変更後は対象のサービスを再起動し、データベースとキューの設定を4つのサービスでそろえてください。

`production.yaml`を置き換える場合は完全なファイルが必要です。パッケージのファイルとはマージされません。ベースの設定と同じ場所にある`production.local.yaml`は、指定した項目だけを上書きします。別の設定ディレクトリは`LOCO_CONFIG_FOLDER`で指定します。権限やデータベースの変更は[パッケージ](../installation/packages/#設定)を参照してください。

## サーバーのアドレス

| productionの環境変数          | 既定値             | 設定する場合                                                                |
| ----------------------------- | ------------------ | --------------------------------------------------------------------------- |
| `BINDING`                     | `localhost`        | ホストやコンテナの外から接続する場合は`0.0.0.0`                             |
| `PORT`                        | `5150`             | 待受ポートを変更する場合                                                    |
| `HOST`                        | `http://localhost` | 利用者向けの完全なURL。必要ならポートも含めます                             |
| `YORISHIRO_MCP_ALLOWED_HOSTS` | 未設定             | 限定した待受アドレスを別のホスト名経由で使う場合のMCPホスト名。カンマ区切り |
| `YORISHIRO_ALLOWED_ORIGINS`   | `[]`               | ブラウザーから許可する接続元をJSON配列で指定                                |

`HOST`は待受アドレスを変更しません。[Dockerの例](../installation/docker-compose/)では`BINDING=0.0.0.0`と`HOST=http://localhost:5150`を明示しています。

別のオリジンのブラウザークライアントには、`YORISHIRO_ALLOWED_ORIGINS`を`["https://assistant.example.com"]`のように設定します。MCPのホスト名検証とは別の設定で、APIキーの代わりにはなりません。`0.0.0.0`や`::`で待ち受ける場合は任意のMCP Hostを受け付けます。限定したアドレスではループバック、待受アドレス、明示的に許可したホストを受け付けます。

## データベースとキュー

| productionの環境変数   | 既定値                                                   | 用途                                                                 |
| ---------------------- | -------------------------------------------------------- | -------------------------------------------------------------------- |
| `DATABASE_URL`         | `sqlite:///var/lib/yorishiro/yorishiro.sqlite3?mode=rwc` | 情報の保存先。PostgreSQLは`postgres://`のURI                         |
| `YORISHIRO_QUEUE_KIND` | データベースのURLに従う                                  | `Sqlite`、`Postgres`、またはValkeyなどのRedis互換キュー向けの`Redis` |
| `QUEUE_URL`            | プロバイダーの既定値                                     | キューの接続URI                                                      |

SQLiteと別ファイルのSQLiteキュー、PostgreSQLとPostgreSQLキュー、またはどちらかのデータベースとValkeyを使います。SQLiteのデータベースとキューは同じファイルにしないでください。別ホストのワーカーにSQLiteファイルを共有する構成は使いません。

PostgreSQLには`vector`と`pg_trgm`拡張が必要です。[Composeの例](../installation/docker-compose/#postgresqlとvalkey)に設定手順があります。接続先を変えても既存のデータは移動しません。[エクスポートとインポート](../guides/import-export/)を参照してください。

## テナント

CommunityとライセンスのないEnterpriseは1テナントです。有効なEnterpriseライセンスがあれば、`YORISHIRO_MAX_TENANTS`で上限を増やせます。`0`は無制限で、初回セットアップが無効になります。負の値は使えません。SQLiteは常に1テナントだけです。

## 検索とログインの制限

| productionの環境変数                    | 既定値   | 意味                                               |
| --------------------------------------- | -------- | -------------------------------------------------- |
| `YORISHIRO_SEARCH_TOKENS_PER_MINUTE`    | `100000` | ワークスペースごとの1分間の検索量。APIとMCPで共有  |
| `YORISHIRO_AUTH_RATE_LIMIT_MAX`         | `10`     | クライアントIPごとの時間枠内のログインと登録の回数 |
| `YORISHIRO_AUTH_RATE_LIMIT_WINDOW_SECS` | `60`     | ログインの時間枠の秒数                             |

検索量は検索文の大きさに基づく概算で、プロバイダーの請求トークン数ではありません。制限に達する場合は、上限を増やす前にリクエストの頻度を下げてください。ログインの値には正の数を指定します。

## APIキー

オーナーと管理者はAPIでワークスペースのキーを管理できます。

| リクエスト                                            | 結果                                               |
| ----------------------------------------------------- | -------------------------------------------------- |
| `POST /api/api-keys`に`{"name":"My assistant"}`を送信 | キーを作成。このレスポンスの`full_key`を保存します |
| `GET /api/api-keys`                                   | 秘密の値を含まない一覧                             |
| `DELETE /api/api-keys/{id}`                           | 即時に失効                                         |

名前は1〜100文字です。クライアントが使うキーを失効させると接続できなくなるため、先に新しいキーに切り替えてください。

## ログ

productionのログはJSONです。通常は`LOG_LEVEL=info`を使い、調査中だけ`debug`にして、終わったら戻してください。`RUST_LOG`を設定するとそちらが優先されます。確認コマンドは[トラブルシューティング](../operations/queue-start-objectives/)に掲載しています。ログや設定を共有する前に認証情報を取り除いてください。

## タイムゾーン

productionの環境変数に`YORISHIRO_TIMEZONE=Asia/Tokyo`を設定するか、設定ファイルの`settings.timezone`を変更します。既定値は`UTC`です。IANAのタイムゾーン名を使い、すべてのサービスを同じ設定で再起動してください。

表示する日時が変わるだけで、記録済みの出来事が起きた時刻は変わりません。不正な名前を指定すると起動できません。
