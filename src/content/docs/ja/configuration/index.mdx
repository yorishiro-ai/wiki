## 設定ファイル

Yorishiro は `config/<environment>.yaml` を読み込みます。環境は `LOCO_ENV` で選択します。ソースから実行する場合の既定値は `development` で、Docker とパッケージでは `production` が設定されます。`LOCO_CONFIG_FOLDER` を使うと、ファイルを置く別のディレクトリを指定できます。

設定ファイルは、`DATABASE_URL` などデプロイ時に決まる値を環境変数から読み取ります。用意した設定ファイルは組み込みのファイルを置き換えます。両者はマージされません。組み込みのファイルの隣にローカル用の上書きファイルを置く場合は、`production.local.yaml` という名前にしてください。

パッケージでインストールした場合は、`/etc/yorishiro/production.yaml` があればそれを読み込み、なければ同梱の `production.yaml.example` を読み込みます。Docker でインストールした場合は `/app/config/production.yaml` を読み込みます。

## サーバーのアドレス

| 変数                          | 既定値                                              | 説明                                                                                                                                                                 |
| ----------------------------- | --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BINDING`                     | `0.0.0.0`（production）、`localhost`（development） | サーバーが待ち受けるインターフェース                                                                                                                                 |
| `PORT`                        | `5150`                                              | 待ち受けポート                                                                                                                                                       |
| `HOST`                        | `http://localhost`                                  | リンクに使う公開 URL です。待ち受けアドレスではありません。development では値が固定され、この変数は無視されます。                                                    |
| `YORISHIRO_MCP_ALLOWED_HOSTS` | 未設定                                              | `/mcp` エンドポイントが追加で受け付ける `Host` の値をカンマ区切りで指定します。既定では `localhost`、`127.0.0.1`、`::1` を受け付けます。ワイルドカードは使えません。 |

クライアントが別のホスト名でサーバーに接続する場合（リバースプロキシ経由など）は、そのホスト名を `YORISHIRO_MCP_ALLOWED_HOSTS` に追加してください。追加しないと MCP リクエストは拒否されます。

Enterprise の機能である OAuth ログインにも、公開コールバック URL が必要です。[Enterprise の設定](enterprise/)を参照してください。

## データベースとキュー

アプリケーションのデータには SQLite または PostgreSQL を使います。キューは別に選択します。何も設定しない場合は、どちらも SQLite ファイルを使うため、外部サービスは不要です。

| 変数                   | 既定値                                                                 | 説明                                                                                                                                           |
| ---------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`         | `sqlite:///var/lib/yorishiro/yorishiro.sqlite3?mode=rwc`（production） | PostgreSQL を使う場合は `postgres://` の URI を指定します。development の既定値は `sqlite://yorishiro.sqlite3?mode=rwc` です。                 |
| `YORISHIRO_QUEUE_KIND` | `DATABASE_URL` に従う                                                  | キューの種類: `Sqlite`、`Postgres`、`Redis`（Valkey など Redis 互換のサービス）                                                                |
| `QUEUE_URL`            | プロバイダーの既定値                                                   | キューの URI。例: `redis://valkey:6379`、`rediss://…`                                                                                          |
| `DB_AUTO_MIGRATE`      | `true`                                                                 | 起動時にデータベースのマイグレーションを適用します。サーバーインスタンスを複数動かし、マイグレーションを別に実行する場合は無効にしてください。 |

サポートする組み合わせは次のとおりです。

- SQLite のデータベースと SQLite のキュー
- PostgreSQL のデータベースと PostgreSQL のキュー
- どちらのデータベースでも Valkey のキュー

それ以外の組み合わせ（SQLite のデータベースと PostgreSQL のキュー、またはその逆）は、起動時に拒否されます。両方に SQLite を使う場合は、別々のファイルにする必要があります。パッケージの既定のキューファイルは `sqlite:///var/lib/yorishiro/yorishiro_queue.sqlite3?mode=rwc` です。既存の環境を移行する場合や別の場所を使う場合は、`QUEUE_URL` を明示的に設定してください。

PostgreSQL には `vector` と `pg_trgm` の拡張が必要です。

キューの規模とワーカープロセスについては、[ワーカーとキュー](workers-and-queues/)を参照してください。

## テナント

| 変数                    | 既定値 | 説明                                                                                                                                                                                                                                                                                                      |
| ----------------------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `YORISHIRO_MAX_TENANTS` | `1`    | テナントの最大数です。有効なライセンスがある Enterprise だけが、これ以外の値を反映します。`0` は無制限を意味し、初回セットアップ用のエンドポイントを無効にします。Community とライセンスのない Enterprise は常にテナントを1つだけ許可し、別の値を設定すると警告をログに出力します。負の値は拒否されます。 |

SQLite では常にテナントを1つだけ許可します。

## 検索クォータ

| 変数                                 | 既定値   | 説明                                                                                                                                                                                                                                                                                                             |
| ------------------------------------ | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `YORISHIRO_SEARCH_TOKENS_PER_MINUTE` | `100000` | ワークスペースが1分間に使用できる検索トークン数です。クエリごとに消費され、API と MCP でクォータを共有します。既定値は高めで、主に自動実行されるクエリの暴走を防ぐためのものです。既定の見積もりでは、日本語のテキストは英語の約半分のトークン数で済むため、同じクォータでより多くの日本語クエリを実行できます。 |

## ログインのレート制限

| 変数                                    | 既定値 | 説明                                                            |
| --------------------------------------- | ------ | --------------------------------------------------------------- |
| `YORISHIRO_AUTH_RATE_LIMIT_MAX`         | `10`   | 1ウィンドウあたりに許可するログインとサインアップのリクエスト数 |
| `YORISHIRO_AUTH_RATE_LIMIT_WINDOW_SECS` | `60`   | ウィンドウの長さ（秒）                                          |

どちらも0より大きい値にする必要があります。

## データベース負荷ガード

負荷ガードを使うと、データベースが混雑しているときに PostgreSQL のデプロイを読み取り専用モードに切り替えられます。既定では無効です。

`YORISHIRO_DB_LOAD_THRESHOLD` には、混雑とみなすアクティブ接続数を指定します。ガードは5秒ごとにサンプリングし、接続数がしきい値以上の状態が30秒続くと読み取り専用モードにします。同じ時間だけ落ち着いた状態が続くと、読み取り専用モードを解除します。運用者が設定した読み取り専用や完全ロックの状態は解除しません。SQLite では何もしません。

| 変数                             | 既定値      | 説明                                                                                  |
| -------------------------------- | ----------- | ------------------------------------------------------------------------------------- |
| `YORISHIRO_DB_LOAD_THRESHOLD`    | `0`（無効） | データベースを混雑とみなす PostgreSQL のアクティブ接続数（この値以上）                |
| `YORISHIRO_DB_LOAD_SUSTAIN_SECS` | `30`        | 混雑または落ち着いた状態が続く必要のある時間です。0より大きい値にする必要があります。 |
| `YORISHIRO_DB_LOAD_POLL_SECS`    | `5`         | サンプリングの間隔（秒）です。0より大きい値にする必要があります。                     |

`yorishiro task db_load_guard` は、メンテナンス状態を変更せずに、1回分のサンプルを報告します。

## ログ

`LOG_LEVEL` でログの詳細度を `debug`、`info`、`warn`、`error` から選びます。`RUST_LOG` も使用でき、こちらが優先されます。production ではログを JSON で出力します。

APIキー、Webhook のシークレット、OAuth の認証情報、OIDC のトークン、ライセンスのオーナー情報はログに出力されません。プロバイダーからのエラーレスポンスは、認証情報を繰り返し含む場合があるため、同様にログに出力されません。アクセスログにはリクエストパスを記録しますがクエリ文字列は記録しないため、OAuth のコードや state の値がログに残ることはありません。

## メール

Yorishiro は既定ではメールを送信しません。有効にするには、設定ファイルに `mailer:` ブロックを追加します。そのうえで、環境変数に `MAILER_HOST`、`MAILER_PORT`（既定値は `587`）、`MAILER_USER`、`MAILER_PASSWORD` を設定します。このブロックは、production で `MAILER_HOST` が設定されている場合にだけ使用されます。

## APIキー

テナントのオーナーと管理者は、`/api/api-keys` でワークスペースのAPIキーを管理します。

- `POST /api/api-keys` は1〜100文字の `name` を受け取り、キー全体をそのレスポンスでだけ返します。
- `GET /api/api-keys` は名前、プレフィックス、ID、作成日時を一覧で返します。キーのシークレットは返しません。
- `DELETE /api/api-keys/{id}` はキーを即座に失効させます。ID が存在しない場合や別のテナントに属する場合は `404` を返します。

リクエストに使っているキー自身も失効できます。これにより、管理者は2つ目の認証情報を用意しなくても古いキーを廃止できます。

## タイムゾーン

既定のタイムゾーンは `UTC` です。別のタイムゾーンを使うには、設定ファイルの `settings.timezone` に `Asia/Tokyo` のような IANA 名を設定して再起動します。ファイル内の既存の環境変数を使った式を残し、`YORISHIRO_TIMEZONE=Asia/Tokyo` を指定して起動することもできます。無効な名前を指定すると起動できません。

```yaml
settings:
  timezone: Asia/Tokyo
```

ワークスペースの詳細、APIキーと監査のレスポンス、ログイベントのタイムスタンプには、このタイムゾーンが使われます。変更しても、記録済みのイベントが発生した時刻や、ジョブの実行時刻と有効期限は変わりません。データベースを共有するすべてのサーバーとワーカーで、同じ値を使ってください。
