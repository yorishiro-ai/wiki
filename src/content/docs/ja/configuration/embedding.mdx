Yorishiro はテキストを埋め込みと呼ばれる数値のベクトルに変換して、意味による検索を可能にします。

## 仕組み

エンティティを作成または更新すると、Yorishiro は保存の完了後にバックグラウンドで埋め込みを生成します。このため書き込みは遅くなりません。処理はワーカーが行うので、[ワーカーを起動しておく必要があります](../workers-and-queues/)。

検索するとき、サーバーはワーカーにクエリの埋め込みを依頼し、結果を待ちます。ワーカーがタイムアウトした場合やプロバイダーが失敗した場合、検索は `503` を返します。気づかないうちにテキストのみの結果へ切り替えることはありません。

ワークスペース内のすべての埋め込みは、同じプロバイダーとモデルを使います。ワークスペースが異なれば、別のものを使えます。

埋め込みのないエンティティがあってもエラーにはなりません。あいまい一致のテキスト検索では引き続き見つかりますが、類似検索では関連度の低い結果になります。たとえば `import_jsonl` でバックアップをインポートした直後がこれに当たります。不足している埋め込みを生成するには、次を実行します。

```console
$ yorishiro task resync_embeddings workspace_id:<uuid>
```

Docker ではコンテナー内で `docker exec <container> yorishiro task resync_embeddings workspace_id:<uuid>` を実行します。

## プロバイダーの選択

モデルを自分のマシンで実行することも、LM Studio、Ollama、vLLM、OpenAI など OpenAI 互換のサービスを使うこともできます。

| 変数                                        | 説明                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `YORISHIRO_EMBEDDING_PROVIDER`              | `local` はこのマシンでモデルを実行します（既定値）。`none` は埋め込みを無効にします。`YORISHIRO_EMBEDDING_BASE_URL` と `YORISHIRO_EMBEDDING_MODEL` の両方を設定すると、この変数の値（`local` や `none` を含む）にかかわらず、OpenAI 互換のサービスが選ばれます。`openai` も同じプロバイダーを選択しますが、この2つの変数が両方とも必要です。 |
| `YORISHIRO_EMBEDDING_BASE_URL`              | OpenAI 互換の埋め込みエンドポイントの URL。例: `http://localhost:11434`。`YORISHIRO_EMBEDDING_MODEL` が必要です。                                                                                                                                                                                                                            |
| `YORISHIRO_EMBEDDING_MODEL`                 | OpenAI 互換のサービスで使うモデル名                                                                                                                                                                                                                                                                                                          |
| `YORISHIRO_EMBEDDING_API_KEY`               | サービスのAPIキー。ローカルのサービスでは空にしてください。                                                                                                                                                                                                                                                                                  |
| `YORISHIRO_EMBEDDING_DIMENSIONS`            | モデルが生成するベクトルのサイズ（既定値は `768`）。ローカルのプロバイダーで使えるのは `768` だけです。`1024` と `1536` は OpenAI 互換のプロバイダー用です。                                                                                                                                                                                 |
| `YORISHIRO_EMBEDDING_SEND_DIMENSIONS_PARAM` | リクエストに `dimensions` フィールドを含めて送信します（既定値は `false`）                                                                                                                                                                                                                                                                   |

## ローカルモデル

`YORISHIRO_EMBEDDING_PROVIDER=local` の場合、Yorishiro は `multilingual-e5-base`（768次元）を使います。日本語を含む多くの言語で良好に動作します。ローカルで使えるモデルはこれだけです。

| 変数                                  | 説明                                                                              |
| ------------------------------------- | --------------------------------------------------------------------------------- |
| `YORISHIRO_LOCAL_MODEL`               | モデル名（既定値は `multilingual-e5-base`）。未知の値を指定すると起動できません。 |
| `YORISHIRO_LOCAL_MAX_SEQUENCE_LENGTH` | 入力の最大長（既定値は `512`）。`16` から `512` までの値にする必要があります。    |

モデルファイル（約1 GiB）は初回の使用時にダウンロードされ、`$HOME/.cache/yorishiro/models/` にキャッシュされます。そのため、サーバーには書き込み可能な `HOME` が必要です。初回の起動ではダウンロードの完了を待ちます。2回目以降はキャッシュを使います。ダウンロードに失敗した場合は、サービスを再起動してください。

オフラインで使うには、作業ディレクトリの `models/<model-id>/` に `model.safetensors` と `tokenizer.json` を一緒に置きます。2つのファイルは両方とも用意するか、両方とも置かないでください。

`YORISHIRO_ONNX_*`、`YORISHIRO_LOCAL_MODEL_PATH`、`YORISHIRO_LOCAL_TOKENIZER_PATH` を使っていた古いリリースからアップグレードする場合は、これらの変数を削除してください。設定されている間は、メッセージを出力して起動に失敗します。

## 検索のタイミング

| 変数                                         | 既定値  | 説明                                                                                          |
| -------------------------------------------- | ------- | --------------------------------------------------------------------------------------------- |
| `YORISHIRO_QUERY_EMBEDDING_TIMEOUT_MS`       | `15000` | 検索がクエリの埋め込みを待つ時間で、これを超えると `503` を返します。最大値は `120000` です。 |
| `YORISHIRO_QUERY_EMBEDDING_POLL_INTERVAL_MS` | `100`   | サーバーが結果を確認する間隔。タイムアウトを超えない値にしてください。                        |
| `YORISHIRO_QUERY_EMBEDDING_RETENTION_SECS`   | `300`   | クエリのリクエストを保持する時間。タイムアウト以上の値にしてください。                        |

## 埋め込みモデルの変更

モデルを切り替えても、既存のエンティティには古いモデルのベクトルが残ります。影響を受ける各ワークスペースを再インデックスしてください。

```console
$ yorishiro task reindex_embeddings workspace_id:<uuid>
```

この処理はワークスペース内のすべてのエンティティの埋め込みを作り直します。処理中は、そのワークスペースの検索が `503` を返します。すべてのエンティティの埋め込みが失敗なく作り直されるまで、検索は元に戻りません。API の `POST /api/migration-jobs/reindex` で再インデックスをキューに登録することもできます（`migration` スコープが必要です）。いずれかのワークスペースのモデルが変わっている場合は、起動時にも再インデックスが実行されます。

失敗した埋め込みジョブは自動では再試行されません。原因を修正したあとで `resync_embeddings` または `reindex_embeddings` を実行して復旧してください。
