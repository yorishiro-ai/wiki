Yorishiro serves the Model Context Protocol over Streamable HTTP at `/mcp`. Send your API key in the `Authorization: Bearer <api-key>` header.

Every tool needs an API key with a minimum scope. Scopes are cumulative: `read` < `write` < `schema` < `migration`. A key with a higher scope can call every tool that needs a lower one. A call without enough scope returns a tool error, not a protocol error.

If your clients reach the server through a hostname other than `localhost`, add that hostname to `YORISHIRO_MCP_ALLOWED_HOSTS` (comma-separated). See [Configuration](../../configuration/).

Your MCP client lists the tools your server actually offers. This page lists the tools in the current release.

## Community tools

### create_entity

Create a new entity.

Required scope: `write`

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `data` | any | Yes | Entity body (JSON object) conforming to the schema's `fields` definition. |
| `entity_type` | string | Yes | entity_type name declared in the schema. |
| `schema_name` | string | Yes | Name of the schema this entity conforms to. The workspace's current active version is used. |

### create_relation

Create a relation between two entities. Properties cannot be edited in place; to change them, delete the relation and recreate it. To retire a relation without losing the record that it existed, use set_relation_status instead of deleting.

Required scope: `write`

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `properties` | any | No | Arbitrary properties attached to the relation (JSON object, defaults to an empty object if omitted). |
| `relation_type` | string | Yes | relation_type name declared in the schema's `relation_types` definition. |
| `source_id` | string (uuid) | Yes |  |
| `target_id` | string (uuid) | Yes |  |

### create_schema

Register a new schema, or add a new version to an existing schema.

Required scope: `schema`

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `definition` | any | No | JSON object conforming to `MetaSchemaDefinition` (name/description/entity_types/relation_types). If a schema with the same name already exists, whether the change is breaking or non-breaking is detected automatically and it is registered as a new version. Mutually exclusive with `template_id`; exactly one of the two must be set. |
| `template_id` | string or null | No | ID of a template to use as the definition instead of supplying one inline. A UUID names one from the tenant's own library (see `list_template_library`); anything else names a built-in (see `list_templates`). Mutually exclusive with `definition`; exactly one of the two must be set. |

### get_entity_drift

Report how an entity stands against the active version of its schema. Entities are migrated lazily, so one written against an older version simply lacks fields added since. Use this to tell an absent field apart from an unfilled one before answering from the entity's data.

### import_jsonl

Bulk-import schemas/entities/relations from a JSON Lines document in the export format. Runs as a single transaction: either every record in `jsonl` is applied, or the first error rolls back everything imported so far.

Required scope: `schema`

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `jsonl` | string | Yes | JSON Lines document in the same format `export_jsonl`/`GET /api/export.jsonl` produces: one `{"kind":"schema"\|"entity"\|"relation","record":{...}}` object per line, newline-separated. |

### migration_dry_run

Count what migrating a schema's entities to its active version would face, without doing it. Reports how many are current, how many are behind but still valid, and how many lack a field the active version requires: the last being the work a migration would have to fill in.

Required scope: `read`

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | string | Yes |  |

### recall_context

Fetch an entity's full body together with its relations and connected neighbors, up to `depth` hops away, in one call.

Required scope: `read`

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `depth` | integer (int64) or null | No | How many hops to traverse outward from the entity (defaults to 1, max 3). |
| `entity_id` | string (uuid) | Yes |  |
| `full` | boolean or null | No | When true, neighbor entities include every field instead of only `x-embed` fields (defaults to false). |
| `limit` | integer (int64) or null | No | Maximum number of relations/neighbors to include per hop (defaults to 20 if omitted). |

### search_entities

Vector similarity search over entities using a natural-language query.

Required scope: `read`

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `entity_type` | string or null | No |  |
| `filter` | any | No | JSONB containment filter matched against entity data, e.g. `{"status": "active"}`. |
| `limit` | integer (int64) or null | No | Upper bound on the number of results returned (defaults to 10 if omitted). |
| `query_text` | string | Yes | Natural-language query text. Vectorized via the embedding provider and matched against entities' `x-embed` field by cosine distance. Also used, as-is, for an auxiliary pg_trgm fuzzy text match against entities that have no embedding. |

### set_relation_status

Set a relation's status to active, deprecated or archived. Retiring a relation this way keeps the record that it existed, which delete_relation does not; graph traversal follows active relations only.

Required scope: `write`

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | string (uuid) | Yes |  |
| `status` | string | Yes | "active", "deprecated" or "archived". Traversal follows "active" relations only. |

## Enterprise tools

These tools are available in the Enterprise edition only.

### list_upstream_changes

List schemas in this workspace whose origin template has changed since the schema was last copied. Use this to discover which schemas have pending upstream updates that have not yet been merged.

Required scope: `read`

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `limit` | integer (int64) or null | No | Maximum number of results (defaults to 50 if omitted). |
| `offset` | integer (int64) or null | No | Number of records to skip (defaults to 0 if omitted). |

### merge_apply

Merge the origin template into a schema, writing the merged definition as the schema's next version. Returns the new schema version and a diff describing whether the merge was breaking. Fails if there are merge conflicts.

Required scope: `schema`

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `schema_id` | string (uuid) | Yes | ID of the schema to merge. |

### merge_preview

Preview what merging the origin template would do to a schema. Returns a list of fields that would be added, updated, kept, or conflicted. Does not write anything.

Required scope: `read`

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `schema_id` | string (uuid) | Yes | ID of the schema to preview a merge for. |
