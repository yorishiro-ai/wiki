Use these steps to install Yorishiro on your own Linux server. If an administrator has given you a URL and API key, skip installation and [connect your assistant](../first-run/#4-connect-an-mcp-client).

Use packages on Ubuntu 24.04 or AlmaLinux 10, with glibc 2.39 or later. Releases provide `amd64` and `arm64` builds. Choose Community (`yorishiro-ce`) or Enterprise (`yorishiro-ee`); only one edition can be installed at a time.

## Install

Download the matching package and `checksums.txt` from [Releases](https://github.com/yorishiro-ai/yorishiro/releases). Replace `<VERSION>` with that release tag. For `arm64`, replace `amd64` in the filename.

On Debian or Ubuntu:

```sh
wget https://github.com/yorishiro-ai/yorishiro/releases/download/<VERSION>/yorishiro-ce-<VERSION>-amd64.deb
sudo apt install ./yorishiro-ce-<VERSION>-amd64.deb
```

On AlmaLinux:

```sh
wget https://github.com/yorishiro-ai/yorishiro/releases/download/<VERSION>/yorishiro-ce-<VERSION>-amd64.rpm
sudo dnf install ./yorishiro-ce-<VERSION>-amd64.rpm
```

## Start

```sh
sudo systemctl enable --now yorishiro yorishiro-worker yorishiro-jobs yorishiro-scheduler
sudo systemctl status yorishiro yorishiro-worker yorishiro-jobs yorishiro-scheduler
```

Continue with [First run](../first-run/) at `http://localhost:5150`. The first embedding-worker start downloads about 1 GiB. Check it with `sudo journalctl -u yorishiro-worker -f`.

## Installed files

| Path                                     | Contents                                                 |
| ---------------------------------------- | -------------------------------------------------------- |
| `/usr/bin/yorishiro`                     | Executable                                               |
| `/etc/yorishiro/production.yaml.example` | Packaged configuration example, updated with the package |
| `/etc/yorishiro/production.yaml`         | Your optional complete configuration                     |
| `/var/lib/yorishiro`                     | SQLite data and queue files, and the `models/` directory |

Enterprise also installs `/etc/yorishiro/LICENSE.enterprise`.

## Configuration

All four services use the same configuration. Without your own file, they use the packaged example and SQLite. No `yorishiro.env` file or `EnvironmentFile=` override is needed.

To customize settings, copy the example only if you do not already have a configuration:

```sh
sudo cp -n /etc/yorishiro/production.yaml.example /etc/yorishiro/production.yaml
sudo chown root:yorishiro /etc/yorishiro/production.yaml
sudo chmod 640 /etc/yorishiro/production.yaml
sudoedit /etc/yorishiro/production.yaml
```

Keep the file readable by the `yorishiro` service user. The permissions above keep any passwords out of other users' access. Back up your existing configuration before editing it. Your file replaces the packaged configuration, so compare it with the new example after an upgrade.

For PostgreSQL, set `database.uri` to its connection URI. Replace the entire conditional queue section with a single `queue:` block: retain the options for your selected provider, set `kind: Postgres` and its `uri`, and remove the other branches and template condition lines. For Valkey, select `kind: Redis` and a `redis://` or `rediss://` URI instead. Editing only `database.uri` does not change the example's queue selection.

To allow connections from another machine, change `server.binding` from `localhost` to `0.0.0.0`, and set `server.host` to the URL users connect to. See [Configuration](../../configuration/).

After editing:

```sh
sudo systemctl restart yorishiro yorishiro-worker yorishiro-jobs yorishiro-scheduler
```

The services can write only under `/var/lib/yorishiro`; keep writable SQLite and model files there. If a unit fails repeatedly, see [Troubleshooting](../../operations/queue-start-objectives/).
