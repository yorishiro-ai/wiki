Use a configuration on this page to run your own Yorishiro server. If you already have a URL and API key, skip installation and [connect your assistant](../first-run/#4-connect-an-mcp-client).

Choose one setup below and save it as `compose.yml`. Replace `<VERSION>` with your chosen [release tag](https://github.com/yorishiro-ai/yorishiro/releases). These examples use Community; change the image suffix from `-ce` to `-ee` for Enterprise.

## SQLite

Use this for a personal installation without an external database.

```yaml
x-yorishiro: &yorishiro
  image: ghcr.io/yorishiro-ai/yorishiro:<VERSION>-ce
  restart: unless-stopped
  environment:
    BINDING: 0.0.0.0
    HOST: http://localhost:5150
    YORISHIRO_EMBEDDING_PROVIDER: ${YORISHIRO_EMBEDDING_PROVIDER:-local}
  volumes:
    - data:/var/lib/yorishiro
    - models:/app/models

services:
  app:
    <<: *yorishiro
    ports:
      - "5150:5150"
  worker:
    <<: *yorishiro
    command: ["start", "--worker=worker-target:shared"]
    healthcheck:
      disable: true
    depends_on:
      app:
        condition: service_healthy
  jobs:
    <<: *yorishiro
    command: ["start", "--worker=job-target:shared"]
    healthcheck:
      disable: true
    depends_on:
      app:
        condition: service_healthy
  scheduler:
    <<: *yorishiro
    command: ["scheduler"]
    healthcheck:
      disable: true
    depends_on:
      app:
        condition: service_healthy

volumes:
  data:
  models:
```

## PostgreSQL and Valkey

Use PostgreSQL for several tenants or workers on different machines. Valkey provides the Redis-compatible queue. Change `change-me` in both database password settings before starting.

Create `init-extensions.sql` beside `compose.yml`:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
```

PostgreSQL runs this file only when its data volume is empty. For an existing database, have its administrator enable those extensions before starting Yorishiro.

```yaml
x-yorishiro: &yorishiro
  image: ghcr.io/yorishiro-ai/yorishiro:<VERSION>-ce
  restart: unless-stopped
  environment:
    BINDING: 0.0.0.0
    HOST: http://localhost:5150
    DATABASE_URL: postgres://yorishiro:change-me@db:5432/yorishiro
    YORISHIRO_QUEUE_KIND: Redis
    QUEUE_URL: redis://valkey:6379
    YORISHIRO_EMBEDDING_PROVIDER: ${YORISHIRO_EMBEDDING_PROVIDER:-local}
  volumes:
    - models:/app/models

services:
  db:
    image: pgvector/pgvector:pg18
    restart: unless-stopped
    environment:
      POSTGRES_USER: yorishiro
      POSTGRES_PASSWORD: change-me
      POSTGRES_DB: yorishiro
    volumes:
      - pg-data:/var/lib/postgresql
      - ./init-extensions.sql:/docker-entrypoint-initdb.d/init-extensions.sql:ro
    healthcheck:
      test: ["CMD", "pg_isready", "-U", "yorishiro"]
      interval: 5s
      timeout: 3s
      retries: 5
  valkey:
    image: valkey/valkey:9.1.2
    restart: unless-stopped
    command: ["valkey-server", "--appendonly", "yes"]
    volumes:
      - valkey-data:/data
    healthcheck:
      test: ["CMD", "valkey-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 5
  app:
    <<: *yorishiro
    ports:
      - "5150:5150"
    depends_on:
      db:
        condition: service_healthy
      valkey:
        condition: service_healthy
  worker:
    <<: *yorishiro
    command: ["start", "--worker=worker-target:shared"]
    healthcheck:
      disable: true
    depends_on:
      app:
        condition: service_healthy
      valkey:
        condition: service_healthy
  jobs:
    <<: *yorishiro
    command: ["start", "--worker=job-target:shared"]
    healthcheck:
      disable: true
    depends_on:
      app:
        condition: service_healthy
      valkey:
        condition: service_healthy
  scheduler:
    <<: *yorishiro
    command: ["scheduler"]
    healthcheck:
      disable: true
    depends_on:
      app:
        condition: service_healthy

volumes:
  pg-data:
  valkey-data:
  models:
```

To use PostgreSQL for the queue too, remove `YORISHIRO_QUEUE_KIND`, `QUEUE_URL`, the `valkey` service, its volume, and its entries under `depends_on`. The queue then uses `DATABASE_URL`.

## Start and connect

Run these in the directory containing `compose.yml`:

```sh
docker compose up -d
docker compose ps
docker compose logs --tail 100 worker
```

The embedding worker downloads about 1 GiB on its first start. The server and other services do not need to load that model. To try saving data without semantic search, run `YORISHIRO_EMBEDDING_PROVIDER=none docker compose up -d` instead.

Open [First run](../first-run/) and use `http://localhost:5150`. If users connect through another address, change `HOST` to their URL. Keep the same database and queue settings on all four services.

## Keep your data

`docker compose down` stops the installation without deleting its named volumes. Do not add `-v` unless you intend to delete those volumes and their data. Updating an image is not a backup; see [Update and back up](../../operations/queue-publisher-cutover/).

## Use a local embedding model offline

Place both files on the host:

```text
models/multilingual-e5-base/model.safetensors
models/multilingual-e5-base/tokenizer.json
```

In the existing `x-yorishiro.volumes` list, replace `models:/app/models` with `./models:/app/models:ro`. Keep any other entries, including `data:/var/lib/yorishiro` in the SQLite example. Recreate the worker with `docker compose up -d worker`.

The container user must be able to read both files. Providing only one prevents the embedding worker from starting. See [Embedding](../../configuration/embedding/) for provider options.
