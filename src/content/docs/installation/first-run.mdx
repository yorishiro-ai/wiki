Install Yorishiro with [Docker Compose](../docker-compose/) or [packages](../packages/) first. If an administrator has already given you a server URL and API key, skip to step 4.

These examples use `http://localhost:5150`. Replace it with your server URL when connecting to another installation. Account creation uses the API, not a web setup screen.

## 1. Check the server

```sh
curl http://localhost:5150/_ping
```

A successful response confirms that the server answers. Search also needs the embedding worker. Its first start downloads about 1 GiB of model files; wait for that worker to finish starting before testing search.

## 2. Create the first account

Check whether setup is needed:

```sh
curl http://localhost:5150/setup/status
```

If `setup_required` is `true`, replace the example email, password, and name, then run:

```sh
curl -X POST http://localhost:5150/setup \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"choose-a-password","display_name":"You"}'
```

Save the returned `api_key` in your password manager. It is shown only once. The response also includes your user, tenant, and workspace IDs.

If setup returns `409`, the installation already has a tenant. Ask its administrator for access. Setup is disabled when `YORISHIRO_MAX_TENANTS=0`.

## 3. Use the API key

Verify the key with a request:

```sh
curl http://localhost:5150/api/api-keys \
  -H 'Authorization: Bearer <api-key>'
```

Replace `<api-key>` with the saved key. Do not include the angle brackets. Keep it private; anyone holding it can use the access it grants.

## 4. Connect an MCP client

In an MCP client that supports remote HTTP servers and custom headers, add:

| Setting      | Value                       |
| ------------ | --------------------------- |
| Server URL   | `http://localhost:5150/mcp` |
| Header name  | `Authorization`             |
| Header value | `Bearer <api-key>`          |

Use your server's address instead of `localhost` if the client runs on another machine. For a hosted instance, use the HTTPS URL supplied by its administrator. Client configuration screens differ; the `/mcp` URL and bearer header remain the same.

Reconnect the client and ask it to list the available schemas. If it can call `list_schemas`, the connection works. An empty list is normal for a new workspace.

Continue with [Use Yorishiro with your AI assistant](../../guides/using-yorishiro/) to save and search your first note. For errors, see [Troubleshooting](../../operations/queue-start-objectives/).

## Inspect the connected context

Ask the assistant to call `whoami`, `discover_workspaces`, and `capabilities`. Check tenant/workspace UUIDs, effective scope, binding, and audit access before changes. Candidate names are display labels, not identities. Discovery does not grant access, and capability scope/grant flags do not guarantee role, resource, or licence authorization.

Workspace-bound keys cannot retarget. Enterprise tenant-bound keys use `X-Workspace-Id` for an authorized workspace. For collaborators and least-privilege client keys, see [Access management](../../guides/access-management/) and [API keys](../../guides/api-keys/). Login recovery is covered in [Troubleshooting](../../operations/queue-start-objectives/#login-recovery).
